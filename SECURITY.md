# Security and misuse reports

Please report security issues, safeguard bypasses (consent check, watermark, label) and misuse **privately**
through GitHub: open the repository's **Security** tab and choose **Report a vulnerability**. Don't open a public
issue for these.

You can expect an acknowledgement within a week. This is a personal open-source project, maintained on a best-effort basis.

## Scope

- This code (application, deployment scripts, infrastructure templates).
- The safeguards described in [RESPONSIBLE_USE.md](RESPONSIBLE_USE.md).

Issues in third-party models or services (Qwen, AudioSeal, AWS, hosted providers) should be reported to those projects.

## Deployments

Each deployment runs in its owner's AWS account. The maintainers have no access to deployments, voice samples or
outputs, and can't remove content generated by others.

## How the code is checked

The `security` workflow runs on every push and pull request, and weekly:

| Scan | Tool | Covers |
|---|---|---|
| Our code | CodeQL (security-extended queries) | The Python code and the GitHub Actions workflows |
| Dependencies | OSV-Scanner | Every package version in `uv.lock` |
| Infrastructure | Trivy | Terraform, Dockerfiles, Docker Compose |
| Secrets | gitleaks (in CI, whole history) and GitHub push protection | Every commit |

Dependabot sends security alerts and proposes weekly updates for Python packages and GitHub Actions. Results are
in the repository's **Security** tab.

## Known findings

These are reviewed and accepted for now, with the reasons. Each dependency entry in
[`osv-scanner.toml`](osv-scanner.toml) covers one package version and expires, so it gets reviewed again; the
infrastructure entries are in [`.trivyignore`](.trivyignore).

**Dependencies held back by the voice model's library.** `qwen-tts` 0.1.1 (the newest release) pins
`transformers==4.57.3` and `accelerate==1.12.0`. That `transformers` needs `huggingface-hub` below 1.0, which holds
`gradio` at 6.17.3, which holds `pillow` below 13. A newer `qwen-tts` unblocks all of them.

| Package | Advisories | Why the risk here is low |
|---|---|---|
| pillow 12.3.0 | 41, all in reading or writing image files | The studio never opens images: it takes audio only, from its single user, through a private tunnel |
| transformers 4.57.3 | 5: loading untrusted models or code, `Trainer`, `save_pretrained` | Only named models pinned to tested commits are loaded; nothing is trained or saved |
| accelerate 1.12.0 | 1: loading a malicious sharded checkpoint | Same: only pinned, tested model commits |

**Infrastructure choices.**

| Finding | Why |
|---|---|
| Outbound traffic to any address on ports 443 and 80 | Models, packages and images come from hosts without fixed addresses; a filtering proxy or VPC endpoints would cost $30+/month. Port 80 carries the OS package mirrors, including the host's security updates. There are no inbound rules at all |
| S3 bucket without versioning | Deleting a voice must really delete the recording |
| S3 encrypted with S3-managed keys, not a customer-managed KMS key | Encrypted at rest either way; a KMS key adds cost and key management a single-user tool doesn't need |
| The local deploy toolbox container runs as root | Short-lived, mounts only the repo; on Linux the scripts run it as your own user |
